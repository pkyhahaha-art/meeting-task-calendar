ตรวจวันที่ 4 ตุลาคม 2026 (Asia/Bangkok) — PEA Meeting & Task Calendar

## ขอบเขตและผลตรวจ

ดำเนินการตาม checklist ในไฟล์ที่ผู้ใช้ส่ง: Database/Supabase, API/Auth, Type Safety, edge cases และความปลอดภัย พร้อมบันทึกข้อผิดพลาดและแก้จุดที่พิสูจน์ได้ ตรวจทั้ง source, production build และ catalog/log ของ Supabase จริง ไม่เปลี่ยนกติกาผู้รับแจ้งเตือน การทำซ้ำ หรือข้อมูลสมาชิกเดิม

| หัวข้อ | ผลตรวจ |
| --- | --- |
| RLS / CRUD | ตาราง public 23 ตารางเปิด RLS ทั้งหมด ตรวจ policies และ grants: สมาชิกแก้ role/status/email ของตนเองผ่าน UPDATE ไม่ได้; ข้อมูล task จำกัดตามผู้สร้าง/ผู้รับ/ผู้ดูแล; ปฏิทินประชุมร่วมสำหรับสมาชิก active คงพฤติกรรมเดิม |
| Foreign keys | 37 constraints ผ่าน validation; ข้อมูลลูกใช้ CASCADE, เจ้าของใช้ RESTRICT และประวัติที่ต้องรักษาใช้ SET NULL ตาม schema เดิม |
| Functions / triggers | ตรวจ SECURITY DEFINER, search_path และสิทธิ์เรียก พบ helper เข้าคิวเปิดให้ client เรียกโดยตรง แก้แล้ว; การเข้าคิวผ่าน RPC ที่ตรวจเจ้าของยังทำงาน |
| PostgreSQL logs | ตรวจ error ย้อนหลัง 24 ชั่วโมง พบปัญหาสิทธิ์ reminders เก่าและข้อผิดพลาดของ SQL fixtures/queries ระหว่างพัฒนา; ไม่เหมารวมเป็นบั๊กแอปปัจจุบัน ตรวจ cron/worker ล่าสุดตอบ HTTP 200 |
| Indexes | เพิ่ม 4 non-unique indexes สำหรับค้นไฟล์แนบตาม event/task และประวัติแจ้งเตือนตาม event/task + เวลา; ไม่เปลี่ยนข้อมูลหรือ uniqueness |
| Session / token | SDK เปิด persistSession, autoRefreshToken และ detectSessionInUrl อยู่แล้ว เพิ่มการกันผลตอบกลับเก่าทับ session/profile ใหม่ และล้าง cache เมื่อสลับบัญชี |
| API errors / edge cases | ตรวจ session/profile ไม่มีข้อมูล, Supabase error, network rejection, logout failure และ error ของรายการอุปกรณ์/การยกเลิกเชื่อมต่อ; เพิ่มข้อความลองใหม่และป้องกัน success เท็จ |
| TypeScript / schema | เปรียบเทียบ Row fields ที่แอปประกาศ 187 คอลัมน์กับชนิดพื้นฐานและ nullability ในฐานข้อมูลจริง แก้ uploaded_by ของ task_attachments ให้รับ null; ไม่ใช่การเทียบทุก enum value/RPC signature โดยอัตโนมัติ |
| Environment / secrets | URL เป็น HTTPS และ browser publishable key มีครบ; real .env ไม่อยู่ใน Git; สแกน src/dist ไม่พบ sb_secret, private-key PEM หรือ JWT ที่ role=service_role ไม่พิมพ์ค่าคีย์ออกมา |
| Storage | meeting-documents / task-documents เป็น private, จำกัดไฟล์ 10 MB; คงการเปิดเอกสารผ่านระบบเดิม |

## การตรวจสอบหลังแก้

- เว็บ: 134 tests ผ่าน, lint ผ่าน, production build ผ่าน; build มี warning ขนาด chunk เดิม ไม่ใช่ข้อผิดพลาด compilation
- SQL: audit_security.sql ใช้ synthetic users/devices และ ROLLBACK ตรวจ helper permissions, valid/invalid pairing, token reuse, disabled account, endpoint overwrite/re-pair และ authorized creator confirmation
- SQL regression: ชุด task/meeting เดิมตรวจการเข้าคิว การทำซ้ำ รายวัน ผู้เข้าร่วม สมาชิก ไฟล์แนบ และ inbox ด้วย transaction + ROLLBACK
- Schema check: scripts/audit-schema.mjs สร้าง SQL แบบ read-only; ผลสุดท้าย 187 checked, 0 missing, 0 mismatched
- Client scan: scripts/audit-client-config.mjs ผ่านหลัง production build; ไม่ตรวจหรือเปิด private VAPID file
- Database: ใช้ migration 202610040001_audit_security_and_indexes.sql กับ Supabase จริงสำเร็จ และตรวจ grants/indexes หลังใช้งาน
- Snapshot ประวัติ 7 วัน ณ การตรวจหลังแก้: email sent 184, email failed 7, push sent 7; scheduled-maintenance completed 168 ครั้ง ตัวเลขเปลี่ยนได้ตามเวลา

## ข้อจำกัดและการเผยแพร่

การตรวจนี้ไม่รับรองว่าไม่มีบั๊กทุกกรณี ไม่ได้ทดสอบการแสดงแบนเนอร์บน iPhone/Android จริงหรือส่งอีเมล/Push ทดสอบให้ผู้ใช้จริง ทดสอบสถานะการเข้าคิวและสิทธิ์โดย rollback; สถานะ sent ในฐานข้อมูลไม่ใช่หลักฐานว่าผู้รับเปิดอ่านแล้ว ไม่มีการแก้หรือส่งซ้ำ 7 รายการประวัติเก่า

เผยแพร่ source และเว็บด้วย workflow GitHub Pages หลังตรวจผ่าน ให้ตรวจ commit ของ deployment ตรงกับ commit ของชุดแก้ audit นี้

หลักการกำหนด search_path และจำกัด EXECUTE อ้างอิง [Supabase Database Functions](https://supabase.com/docs/guides/database/functions) และการตรวจนโยบายอ้างอิง [Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security)
